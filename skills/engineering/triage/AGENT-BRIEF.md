# Agent brief

A brief is the comment that makes an issue `ready-for-agent`. An agent (or a
person) with no access to the triage conversation must be able to start work
from it alone. It outlives the conversation, so write facts, not chat.

## Template

```markdown
> *Generated by an AI agent during triage.*

## Brief

**Goal**: one sentence, the observable behavior after the change.

**Context**
- Relevant code: `path/to/file.rs:120-180` (`symbol_name`), found by searching
  the index for "...".
- Glossary terms: **Term** (meaning in this repo).
- Related: #12 (blocked by), ADR 0004.

**Verified**: how the bug was reproduced or the claim checked, with the exact
command and its output, or "not verified" and why.

**Acceptance**
- [ ] Observable check 1
- [ ] Observable check 2

**Out of scope**: what not to touch.

**Suggested seams**: public interfaces to test through, one line each.
```

## Rules

- Paths and symbols, not vague areas ("somewhere in the indexer").
- Acceptance checks a reviewer can tick without asking you.
- No solution design beyond what triage actually decided; leave the rest to
  the implementer.
- For `ready-for-human`, add **Why not an agent**: judgment calls, credentials,
  manual testing, external coordination.
