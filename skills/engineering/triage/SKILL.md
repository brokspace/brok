# Triage

Keep the issue tracker honest: every issue gets one category, one state, and
enough context for whoever picks it up next.

The tracker commands and label strings should have been provided in
`docs/agents/issue-tracker.md` and `docs/agents/triage-labels.md`. If they are
missing, tell the user to run `/setup-brokspace` and stop. Judge requests
against `SCOPE.md` if the repo has one.

Every comment you post starts with this line:

```
> *Generated by an AI agent during triage.*
```

## Roles

- Category (exactly one): `bug`, `enhancement`.
- State (exactly one): `needs-triage`, `needs-info`, `ready-for-agent`,
  `ready-for-human`, `wontfix`.

Usual path: unlabeled, then `needs-triage`, then one of the other four.
`needs-info` returns to `needs-triage` when the reporter answers. A pull
request from outside the team is an issue with code attached: same roles,
read against the diff. If an item carries two states, stop and ask.

## When asked "what needs attention"

List, oldest first, with counts and one line each: unlabeled items,
`needs-triage` items, and `needs-info` items where the reporter replied after
the last triage note. Tag each line `[issue]` or `[PR]`. Let the user pick.

## Triage one item

1. **Read everything**: body, comments, labels, prior triage notes, and the
   diff for a PR.
2. **Check the codebase**: search the index (`brok search`, or the
   `brok_search` tool) for an existing implementation of the request by
   concept, and say where you looked. Read `.out-of-scope/` for a matching
   past rejection; see [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md).
3. **Recommend** category and state with reasons. Wait for the user.
4. **Verify**: reproduce a bug from its steps, or run the tests for a PR.
   Report confirmed, not reproduced, or not enough detail.
5. **Fill gaps** if needed: call the Skill tool with "grilling" and resolve
   open questions with the user, one at a time.
6. **Apply** the outcome:
   - `ready-for-agent`: post a brief following [AGENT-BRIEF.md](AGENT-BRIEF.md).
   - `ready-for-human`: same brief, plus why it cannot be delegated.
   - `needs-info`: post the notes template below.
   - `wontfix`: close as not planned. Already implemented: point to the code.
     Rejected idea: add an `.out-of-scope/` entry and link it.

Confirm label changes, comments and closes before doing them. If the user
says "move #42 to ready-for-agent", do it and ask whether to add a brief.

## Needs-info template

```markdown
## Triage notes

**Established so far:**
- ...

**Still needed from @reporter:**
- specific question 1
- specific question 2
```
